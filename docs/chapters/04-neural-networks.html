4  Neural Networks

At this point you know how to handle data files, manipulate tables, and create plots.

In this chapter we will build neural networks that learn patterns directly from data. We start with a hands-on example (generate data, train, evaluate) before unpacking the theory. The framework is Lux.jl, a modern Julia library that keeps model parameters and state explicit.

4.1 Your first neural network: Sauna Satisfaction Predictor

Let’s skip the theory for now and train a neural network end to end. Data goes in, a model learns, predictions come out. Everything fits on your laptop in under a minute.

4.1.1 The problem

In an alternate universe, the Geological Survey of Finland has an office sauna in every building, and geologists are allowed to use it after a single qualifying event: surviving a long meeting with geophysicists.

Since this is a government office sauna, a visitor log is maintained with the seriousness usually reserved for core samples. For each sauna visit the log records three things:

  • Sauna temperature (°C)
  • Outside temperature (°C)
  • Minutes since last coffee

After the session the visitor assigns a Satisfaction Score between 0 and 1, where 0 means “this was a management idea” and 1 means “I love my job.”

We will train a small neural network to predict the Satisfaction Score from these three inputs. This is a regression problem (the output is a continuous number) rather than classification, so we will use mean squared error (MSE) as the loss function.

4.1.2 The training data

The logbook has 200 visits. The hidden satisfaction rule works like this: satisfaction peaks around 80 °C, gets a boost when it is freezing outside, drops when the last coffee was too long ago, and includes random noise because people are unpredictable. The relationships are non-linear, so a straight line cannot capture them, but a small neural network can.

4.1.5 Read the data and normalise

We read the file, parse the numbers, and normalise each feature to zero mean and unit variance so the network treats all inputs equally:

lines = readlines("sauna_log.txt")
header = split(lines[1], ",")
data = reduce(hcat, [parse.(Float32, split(l, ",")) for l in lines[2:end]])

# rows: sauna_temp, outside_temp, coffee_min, score
X_raw = data[1:3, :]
Y     = data[4:4, :]

# Normalise inputs
mu  = mean(X_raw, dims = 2)
sig = std(X_raw, dims = 2)
X   = (X_raw .- mu) ./ sig

@printf "Visits: %d   Features: %s   Output: %s\n" size(X, 2) string(size(X)) string(size(Y))
Visits: 200   Features: (3, 200)   Output: (1, 200)

rng = Xoshiro(123)

4.1.7 Build the model

One hidden layer, 8 neurons, tanh activation, and a single linear output. No sigmoid at the end because this is regression, not classification.

model = Chain(
    Dense(3 => 8, tanh),
    Dense(8 => 1)
)
Chain(
    layer_1 = Dense(3 => 8, tanh),                # 32 parameters
    layer_2 = Dense(8 => 1),                      # 9 parameters
)         # Total: 41 parameters,
          #        plus 0 states.

In Lux the model is just a blueprint. Parameters and state are initialised separately:

ps, st = Lux.setup(rng, model)
((layer_1 = (weight = Float32[-0.71197426 0.5440084 -0.9027876; -0.62075335 -0.5090574 1.4643831; … ; 0.7166022 -0.17811993 0.5175801; -1.5047655 -0.24505515 1.5166628], bias = Float32[0.23182774, -0.18704338, 0.17974052, 0.15094592, -0.023374384, 0.47140634, -0.18232994, 0.08013492]), layer_2 = (weight = Float32[-0.48614922 0.6079607 … -0.5020537 -0.45970005], bias = Float32[0.24544002])), (layer_1 = NamedTuple(), layer_2 = NamedTuple()))

This separation means you can save parameters, swap them between models, or pass them to a differential equation solver without any fuss.

4.1.8 Define the loss function

Mean squared error (MSE): predictions far from the truth get penalised quadratically.

function mse_loss(model, ps, st, data)
    x, y_true = data
    y_pred, st_new = model(x, ps, st)
    loss = mean((y_pred .- y_true) .^ 2)
    return loss, st_new, ()
end
mse_loss (generic function with 1 method)

4.1.9 Train the network

Adam optimiser, 500 epochs:

opt = Adam(0.01f0)
tstate = Training.TrainState(model, ps, st, opt)

for epoch in 1:500
    _, loss, _, tstate = Training.single_train_step!(
        AutoZygote(), mse_loss, (X_train, Y_train), tstate
    )
    if epoch == 1 || epoch % 100 == 0
        @printf "Epoch %4d  MSE = %.6f\n" epoch loss
    end
end

4.1.11 Predict new scenarios

Now for the important part. HR wants to know: what sauna settings should they recommend after the next geophysicist meeting?

scenarios = [
    (sauna=80, outside=-20, coffee=10,
     label="Perfect: 80°C, -20°C, fresh coffee"),
    (sauna=65, outside=5,   coffee=100,
     label="Sad: lukewarm, mild day, stale coffee"),
    (sauna=95, outside=-25, coffee=30,
     label="Extreme: 95°C, deep winter, recent coffee"),
    (sauna=75, outside=0,   coffee=60,
     label="Average: 75°C, 0°C, 1 h since coffee"),
]

function predict_score(s, model, ps, st, mu, sig)
    x = Float32.([(s.sauna  - mu[1]) / sig[1],
                  (s.outside - mu[2]) / sig[2],
                  (s.coffee  - mu[3]) / sig[3]])
    pred, _ = model(reshape(x, 3, 1), ps, st)
    return pred[1]
end

println("Sauna Satisfaction Predictions")
println("─"^40)
for s in scenarios
    sc = predict_score(s, model,
        tstate.parameters, tstate.states, mu, sig)
    @printf "  %-38s  %.2f\n" s.label sc
end
println("─"^40)

Try it yourself
  1. Add a fourth input, “meeting duration (minutes).” Does the network improve?
  2. Make it deeper: 3 => 16 => 8 => 1. Does it overfit on 200 samples?
  3. Swap tanh for relu. How does the test error change?

4.2 What is a neural network?

A neuron multiplies inputs by weights, adds a bias, and passes the result through a non-linear activation:

\[ z = \sigma\!\bigl(\mathbf{w}^\top \mathbf{x} + b\bigr) \]

Stack neurons side by side to get a layer; chain layers to get a network. Our Chain(Dense(3 => 8, tanh), Dense(8 => 1)) is two layers.

4.2.1 How does it learn?

Four steps, repeated many times:

  1. Forward pass: run data through the network.
  2. Loss: measure how wrong the predictions are.
  3. Backward pass: compute gradients of the loss with respect to every weight using automatic differentiation.
  4. Update: nudge each parameter to reduce the loss (Adam, SGD, etc.).

That is the entire recipe.
